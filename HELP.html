KotOR Maya Importer (V114) — User Guide

This tool imports characters, standalone props, animations, and complete levels from Star Wars: Knights of the Old Republic into Autodesk Maya 2024. It reads your own installed copy of the game and never changes anything in the game folder.

Getting set up

After installing (drag install.py into the Maya viewport — see the README), open the window from the KotOR menu or the KotOR shelf button. The Setup section at the top needs only the plug-in and game location, remembered between sessions:

FieldWhat to do
Plug-in Press Load once. The status shows Loaded (114.0.0), shaders found when everything is in order. The viewport shaders are found automatically — there is nothing else to configure.
KotOR install Your game folder — the one containing chitin.key and swkotor.exe. Typical locations:
GOG: C:/GOG Games/Star Wars - KotOR
Steam: C:/Program Files (x86)/Steam/steamapps/common/swkotor

There is no Export folder setting. Maya needs decoded image and audio files on disk, so the importer manages them automatically under Documents/maya/KotorMayaImporterCache/V114. Use Open Import Cache after an import when you need the exact location.

Tip: hover over any field or button in the window — every control has a tooltip explaining exactly what it does.

The window at a glance

  • Setup — load the plug-in and locate KotOR.
  • Character tab — import an appearance-backed player body, NPC, creature, or droid.
  • Prop tab — import a standalone installed model as static geometry.
  • Animations tab — list and inspect animation clips, and pick one for the character import.
  • Level tab — import a complete level and control what is visible.
  • Result — a summary of the last import, with buttons to open the managed cache and the log.

Supported game data

The importer reads the following KotOR 1 formats directly from the selected game installation:

CategoryFormats and content
Archives and indexesKEY, BIF, RIM, and ERF
Models and animationBinary MDL and MDX, including meshes, skeletons, skin weights, clips, events, rooms, equipment, lights, emitters, dangly meshes, AABB trees, and lightsaber data
Textures and materialsTPC, TGA, and TXI, including diffuse textures, alpha, lightmaps, environment maps, bump materials, water, grass, additive and punch-through materials, and animated texture sequences
Tables and names2DA and TLK
Level layoutLYT, VIS, and WOK
Levels and objectsIFO, ARE, GIT, UTC, UTP, UTD, UTI, UTS, UTW, UTT, UTE, and UTM
AudioWAV audio and KotOR's packaged MPEG-compressed sound streams, imported as Maya audio nodes

The result is a native Maya scene. The importer does not export or write game files.

Every ... button opens a browser with a live filter box — start typing to narrow the list, then double-click an entry (or select it and press Select).

Character tab

Two ways to import, chosen with the buttons at the top:

Manual model

You choose each character piece yourself. Only Model is required — everything else is optional.

FieldMeaning
ModelAn installed character body or race model referenced by appearance.2da. Standalone models belong on the Prop tab; player bodies commonly start with pmb (male) or pfb (female).
HeadA separate head, attached at the body's head attachment point. Browse starts on male heads (pmh) — change the filter to pfh for female heads. Leave empty for models with a built-in head.
Body textureAn exact texture to use on the body. Browse starts filtered to the current model's name, because body textures are named after the body they fit.
Right hand / Left handAn item to place in each hand (browse starts on weapons, w_). The body must have the matching hand attachment point — most humanoid bodies do.
Mask/gogglesA head-slot item (browse starts on i_mask). Requires a separate Head with a goggle attachment point.

NPC / creature

Import anyone from the game with everything they wear and carry, exactly as the game defines them.

  • Creature ... with the level field empty browses every NPC, creature, and droid in the game — over 1,600 entries, with the filter box to search. Picking one fills everything in.
  • Or pick a Level (module) first to browse just that level's inhabitants.

Shared fields

FieldMeaning
LabelNames the imported group in your scene and its managed cache subfolder. Filled automatically from your choices if you leave it empty — it's just a name, it doesn't change what gets imported.
AnimationOptional. One clip, baked as regular Maya keyframes at 30 fps during the import. Use Choose... (or the Animations tab) to pick from the model's real clip list. Leave empty for the bind pose.

Press Import Character / Model. The result appears as a single group in your scene named KOTOR_STARTER_PLAYER_<LABEL>_ROOT.

Prop tab

The Prop tab separates standalone installed models from character bodies and heads using the game's own appearance.2da and heads.2da tables. Choose a model, optionally change its label, then press Import Prop / Standalone.

Props are always static: no character joints, skin binding, or animation is invented. The result is one KOTOR_PROP_<LABEL>_ROOT. Every authored rendered texture must be checked against the selected KotOR installation. If the retail installation itself lacks an authored texture, V114 still imports the exact source geometry, uses its source diffuse color, and shows a successful-import warning with the exact missing resref. It never substitutes a white material, copied asset, or guessed texture.

Animations tab

  1. Enter or browse a Model, then press List — every clip that model can play appears, including clips inherited from its base skeleton.
  2. Click a clip to see its details (length, transition time, where it comes from, how many events it carries).
  3. Import + Play imports that exact model and clip, bakes it as Maya keys, and starts continuous timeline playback. If an imported character is already active, the UI preserves it until the new import succeeds, then replaces it. No overlapping review copy or nonempty-scene dialog is created.
  4. Set Only puts the model and clip on the Character tab without importing — it bakes on that tab's next import.
  5. Bind Pose stops playback and resets the selected/current imported character to its recorded bind pose. It removes only that character's joint animation curves and also clears the Character tab's next-import animation field. If several imported characters exist, select the root you want (or anything below it) first.
  6. Events prints the clip's event list to the Result panel. Events are information only — they never fire.

Listing, selecting, and inspecting are read-only: they never change your scene. Only the explicit Import + Play button imports and starts playback.

Maya Y-up / KotOR Z-up

The Global up axis button in Setup shows the current working convention and switches Maya globally between Maya Y-up and KotOR Z-up. Maya rotates its working views; the importer does not rotate or rewrite existing scene objects or source transforms.

Level tab

  1. Level (module) ... — pick from the list of levels installed with your game. The Area field fills in automatically.
  2. Leave Baked lighting on for the game's baked light look, or turn it off for plain textures.
  3. Press Import Full Level.

The level arrives as one group, KOTOR_LEVEL_<AREA>_ROOT, organized into subgroups (rooms, doors and placeables, creatures, cameras, sounds, and so on).

After a successful level import, the panel turns off any stale Maya isolate-view state and frames the ordinary room core. Enormous authored sky or space shells remain imported and visible, but they are excluded from the automatic framing calculation so the actual level cannot appear missing or as a tiny dot.

KotOR 1 swoop/minigame modules are complete level imports too. Taris, Tatooine, and Manaan include their installed track hooks, obstacle placements, rendered obstacle models, and hidden source collision volumes. The importer does not invent offsets or bundle any game asset.

KotOR 1 cinematic/STUNT modules retain authored no-model room entries, native reference nodes, source-only emitter markers, sky textures, optional walkmesh data, additive displays, and partially transparent placeables. Missing authored lightmaps are reported as source warnings while the level still imports. After a successful import the panel forces a Viewport 2.0 refresh so newly connected file and shader graphs draw immediately.

Show in scene

The importer always brings in the complete level. The checkboxes control what is visible afterwards — unchecked parts are hidden, not skipped, and nothing is ever deleted:

  • Ticked by default: rooms, doors & placeables, NPCs / creatures, grass, lights, particle FX, water — what the game shows.
  • Unticked by default: waypoints, stores & items, triggers & encounters, cameras, sounds, source collision — markers and technical extras, including walkmesh and minigame obstacle audit geometry.
  • Everything / Area only are one-click presets; Apply re-applies your choices to the level already in the scene, any time.

Result panel

After every import the Result panel shows the import summary (counts of meshes, textures, joints, and so on), the imported-root count, and — for levels — which parts were hidden by your Show-in-scene choices. Open Import Cache and Open Log jump straight to the files the import wrote.

PROP IMPORTED - RETAIL ASSET INCOMPLETE means the prop did import, but the installed retail data lacks one or more authored textures. The result and warning list those resrefs; the affected surface uses source diffuse color and no substitute asset. LEVEL IMPORTED WITH SOURCE WARNINGS likewise means the level imported successfully. Open the log to review retained source-only emitters or missing authored lightmaps.

Dialogs you may see

DialogWhy, and what to do
“Cannot import” with a list Something needed is missing (a required field is empty, the plug-in not loaded). Each line says exactly what to fix.
“CONFLICT: … loaded” An older version of the importer plug-in is loaded. Start a new scene, unload the old version in Windows > Settings/Preferences > Plug-in Manager, then press Load again.

Tips

  • Imports may coexist in one scene without a warning. Levels especially can contain thousands of objects, so keep only what the scene actually needs. Import + Play automatically replaces the active review character after a successful animated import.
  • View imports with Viewport 2.0, Smooth Shading, and Textured display on (press 6). That's what the materials are built for.
  • Imported sounds don't play by themselves — select a sound and use Maya's time-slider audio controls.
  • Saved scenes keep working as long as the importer stays installed and its managed cache (which holds the textures) stays where it was.
  • Sharing a scene with someone else? They need this package installed too, plus the relevant managed-cache folder or repathed textures.

Troubleshooting

ProblemFix
Load says the plug-in failed Confirm you're on Maya 2024 (64-bit, Windows) and that the .mll still has all 16 .ogsfx files beside it. If Windows blocked the downloaded file: right-click the .mll > Properties > Unblock. Reinstalling (drag install.py again) restores a complete set.
Status says shader files are missing The .mll and its 16 .ogsfx files must stay in one folder. Reinstall to restore them.
“That folder has no chitin.key” KotOR install must point at the game's main folder, not a subfolder like data or modules and not the launcher folder.
Materials look green, white, or flat Switch to Viewport 2.0 with textured display (press 6). Use Open Import Cache and confirm that import's cache still exists. Some materials are intentionally transparent, glowing, or additive — look from another angle or against a darker background.
The animation doesn't move On the Animations tab use Import + Play, or choose an exact clip on the Character tab and import it. The first path starts playback automatically; the Character-tab path bakes the keys and waits for Maya's Play button. Some clips move only part of the body.
Sound is silent That's normal — sounds import as Maya audio nodes but don't auto-play, and in-game volume/looping behavior isn't simulated. Use the time slider's audio options for review.
An import failed partway The scene may contain a partial result. Check the Result panel and Open Log for the reason, then start a new scene before trying again — don't import repeatedly into the partial scene.
Maya is slow after a level import Full levels are big. Hide what you don't need with the Show-in-scene checkboxes, keep one level per scene, and save before importing.
The window is gone Reopen it from the KotOR menu or the shelf button.
Maya won't let the plug-in unload The current scene still uses the importer's materials. Save if needed, start a new scene, then unload.

FAQ

QuestionAnswer
Can it export back to the game? No. This tool is import-only, by design.
Does it work with KotOR II? No. KotOR 1 only — don't point it at a KotOR II installation.
Other Maya versions? It is built for Maya 2024 on Windows, 64-bit. Other versions are not supported.
Does it see my installed mods? It reads the game's original data files. Loose files in the game's Override folder are not used.
Where do the textures go? Into Documents/maya/KotorMayaImporterCache/V114/<label>. The UI creates and reuses this automatically. Your Maya scene references textures from there, so keep the folder (or repath the file nodes if you move it).
Is this legal to use? The package contains no game assets and reads only your own installed copy. Anything it writes to the managed cache is derived from your copy — keep it for personal use and don't redistribute it.
Why can't I undo an import? Imports create thousands of objects; undo support for that is impractical. Save important Maya work before importing. The UI does not discard or clear the scene automatically.
